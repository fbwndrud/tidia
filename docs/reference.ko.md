# Tidia 상세 안내

[English](reference.md) · [README](../README.ko.md)

README에서 뺀 것들입니다. 밴드 키, 명령, 설정, 사전, 출력 규칙. 대부분은 몰라도 됩니다. 사전, 규칙, 모든 설정은 Claude에게 말하면 됩니다([말로 바꾸기](#말로-바꾸기)).

## 밴드

입력창 위 밴드는 정리가 진행 중일 때만 알려 줍니다(`✨ 정리 중…`, Enter 뒤에는 `✨ 정리 끝나면 보내요`). 그 밖에는 비어 있습니다. `debug`를 켜면 미리보기와 배운 단어도 보여 줍니다. 버튼은 없습니다.

키보드로 친 글과 ↑로 불러온 글은 정리하지 않습니다.

## 명령

| 명령 | 동작 |
|------|------|
| `/tidia` | 상태 |
| `/tidia on` / `off` | 이 세션에서 켜기·끄기 |
| `/tidia settings` | 설정과 현재 값 목록 |
| `/tidia set <설정> <값>` | 설정 바꾸기. 예: `/tidia set style minimal` |
| `/tidia dict` | 사전 창 열기(창이 들어갈 자리가 없으면 글 목록) |
| `/tidia dict list` | 사전 출력 |
| `/tidia dict add <단어>` | 원하는 표기로 쓸 단어 추가 |
| `/tidia dict add <들린 말> = <원래 말> [--project]` | 자주 잘못 받아써지는 말 추가 |
| `/tidia dict remove <단어>` | 항목 삭제 |
| `/tidia dict build` | 이 프로젝트에서 넣을 이름 찾기(먼저 물어봄) |
| `/tidia rules` | 출력 규칙 목록(조건, 켜짐/꺼짐) |

## 말로 바꾸기

아래는 모두 Claude에게 말하면 됩니다. 명령을 칠 필요가 없습니다. Claude는 Tidia 전용 도구 세 개(사전, 규칙, 설정)로 바꿉니다.

| 이렇게 말하면 | 바뀌는 것 | 먼저 묻나 |
|---|---|---|
| "받아쓰기 정리 잠깐 꺼 줘." / "다시 켜 줘." | 정리 켜기/끄기, 이 세션만 | 아니오 |
| "Tidia 설정 뭐야?" / "내 출력 규칙 보여 줘." | 없음, Claude가 읽기만 함 | 아니오 |
| "내 말 그대로 두고 군말만 빼 줘." | `style minimal` | 예 |
| "영어 용어는 코드만 영어로 바꿔 줘." | `english_terms low` | 예 |
| "받아쓰기 정리는 haiku로 해 줘." | `model haiku` | 예 |
| "내가 고친 거 학습하지 마." | `learn off` | 예 |
| "사전 바꾸기 전에 물어봐." | `dict_approval ask` | 예 |
| "말 멈출 때마다 정리해 줘." | `polish_on pause` | 예 |
| "받아쓰기 정리 자세히 보여 줘." | `debug on` | 예 |
| "사전 없이 정리해 줘." | `dictionary off` | 예 |
| "Tidia가 뭘 했는지 메시지에 보여 줘." / "받아쓴 원문을 정리본 위에 보여 줘." | `message_view labeled` / `full` | 예 |
| "표시를 깔끔, 할 일, 그대로로 바꿔 줘." | `bubble_labels` | 예 |
| "받아쓴 원문은 보내지 마." | `attach_raw off` | 예 |
| "Tidia 표시를 일본어로 해 줘." | `ui_language ja` | 예 |
| "버그 얘기할 땐 증상, 재현, 기대 순서로 정리해 줘." | 출력 규칙 추가 | 예 |
| "버그 규칙 켜 줘." / "그 규칙 지워 줘." | 규칙 켜기, 끄기, 삭제 | 예 |
| "아니 그거 Tailscale이야." / "Tailscale을 음성 사전에 넣어 줘." | 사전 항목 | [사전](#사전) 참고 |
| "취소해." | Claude가 방금 한 변경 | 위와 같음 |

"먼저 묻나"는 허용/거절 대화상자입니다. Claude가 채팅으로 묻지 않습니다. Claude Code 권한 모드가 이미 Tidia 도구를 허용하면 대화상자 없이 바뀝니다. 정리 켜기/끄기와 사전 변경은 debug가 꺼져 있어도 한 줄로 보여 주고, 설정과 규칙 변경은 debug를 켜면 보여 줍니다.

## 설정

Claude에게 말하거나, `/tidia set`, `/config`, 또는 설치할 때 `claude plugin install … --config key=value`로 바꿉니다(on/off 설정은 거기서 `true`/`false`).

| 설정 | 값 | 기본값 | 설명 |
|------|----|--------|------|
| `style` | `polish`, `minimal` | `polish` | polish: AI에게 보낼 간결한 메시지로 다듬고 잡담은 뺌. 한 가지 말은 줄글, 여러 요청은 목록, 출력 규칙 적용. minimal: 말한 표현 그대로 줄글로, 군말과 말하다 취소한 부분만 뺌. 출력 규칙은 적용 안 하고, 정리본 검사가 더 엄격함(바꿀 수 있는 단어가 더 적음). 0.1.21 전에 저장한 `light`는 minimal로, `auto`·`markdown`·`custom`은 polish로 바뀜(markdown과 custom 배치는 출력 규칙으로 옮김). |
| `english_terms` | `auto`, `off`, `low`, `medium`, `high` | `auto` | 소리 나는 대로 적힌 영어 용어를 어디까지 영어로 되돌릴지. low: 코드. medium: 제품·언어 이름까지. high: 기술 용어까지. auto는 받아쓴 언어에 따라 정함. |
| `model` | `sonnet`, `haiku`, `opus` | `sonnet` | 정리에 쓰는 모델. haiku가 가장 빠르고 저렴, opus가 가장 느림. |
| `learn` | `ask`, `off` | `ask` | ask: 받아쓴 단어를 같은 식으로 두 번 고치면 사전에 추가. |
| `dict_approval` | `auto`, `ask` | `auto` | auto: 최근 받아쓴 말에서 잘못 알아들은 단어는 발음이 비슷하면 Claude가 묻지 않고 넣고, Claude가 넣은 항목도 묻지 않고 지움. 바꿀 때마다 알려 줌. 그 밖의 항목을 바꾸거나 지울 때는 물음. ask: Claude의 사전 변경을 모두 먼저 물음. |
| `polish_on` | `enter`, `pause` | `enter` | enter: Enter를 누를 때 한 번 정리. 모델 호출이 가장 적고, 보내기가 몇 초 기다림. Enter 때 정리한 메시지는 데스크톱과 터미널에서 `message_view`대로 보임. 다른 화면(VS Code)에서는 메시지 아래 기록 줄로 알려 줌. pause: 말을 멈추면 정리해서 입력창에 넣음. Enter로 나갈 글을 미리 봄. 멈출 때마다 모델 호출, 말을 이어 가면 취소. 들어오기 전에 누른 Enter는 정리를 기다림. |
| `debug` | `on`, `off` | `off` | Tidia가 하는 일을 보여 줌. 밴드의 미리보기, Claude가 바꾼 내용 알림, 정리 없이 나간 이유. off면 밴드는 정리 중일 때만 알려 줌. |
| `dictionary` | `on`, `off` | `on` | 사전과 대화 속 파일·식별자 이름을 표기 힌트로 보내고, 고친 단어를 배움. off면 힌트 없이 정리하고 배우지 않음. 항목은 그대로 둠. |
| `message_view` | `tidied`, `labeled`, `full` | `tidied` | Enter 때 정리한 메시지를 데스크톱과 터미널에서 보여 주는 방식. tidied: 보낸 글만. labeled: Tidia가 한 일(`→ 간결화`/`→ 목록화`/`→ 최소 수정`, 조건이 붙은 출력 규칙을 적용했으면 `· 규칙 적용`) 아래 보낸 글을 줄마다. full: 말한 원문 아래 같은 내용. 엔진의 원래 줄 글만 바꾸므로 데스크톱 말풍선의 시간·복사·되돌리기·fork 줄이 그대로 남음. 0.1.22 전에 저장한 `show_raw show`는 `full`로, `hide`는 `labeled`로 옮김. |
| `bubble_labels` | 80자까지 자유 입력 | 비어 있음 | `message_view`가 labeled·full일 때 보일 문구, 간결화/목록화/최소 수정 순서로 `/`로 나눔("정리/할 일/그대로"). 비운 칸은 인터페이스 언어의 기본 문구. `none`이면 지움. |
| `attach_raw` | `on`, `off` | `on` | 정리된 메시지마다 받아쓴 원문을 한 줄로 함께 보냄. Claude는 보고 내 메시지 화면에는 안 보이며, 정해진 안내 문장과 원문만 들어 있음. 정리가 잘못돼도 Claude가 원래 뜻을 알 수 있게 함. [Claude가 받는 것](architecture.ko.md#4-claude가-받는-것) 참고. |
| `ui_language` | `auto`, `en`, `ko`, `ja`, `zh`, `es`, `de`, `fr`, `pt` | `auto` | mod 문구의 언어. auto는 Claude Code 언어 설정을 따름. |

`/tidia set`은 대화형 세션에서 동작합니다. `claude -p` 실행에는 플러그인 설정 행이 없으니 `claude plugin install … --config key=value`나 `claude plugin configure`를 쓰세요.

## 사전

사전에는 지키고 싶은 표기가 들어갑니다. 항목은 정리 모델에 주는 힌트이고, 무조건 찾아 바꾸지 않습니다. 그래서 소리만 비슷하고 뜻이 다른 말은 그대로 둡니다.

- **Claude.** 받아쓴 원문이나 내가 고쳐 말한 것("아니 그거 Tailscale야")으로 잘못 알아들은 단어가 확실하면 Claude가 사전에 넣고 한 줄로 알려 줍니다. "취소해"라고 하면 지웁니다. 최근 받아쓴 말에 나온 단어는 발음이 비슷할 때 묻지 않고 넣고, Claude가 넣은 항목은 묻지 않고 지웁니다. 이런 변경은 debug가 꺼져 있어도 항상 보여 줍니다. 그 밖의 항목(내가 넣은 것, 패널에서 승인한 것, 내 수정에서 배운 것)을 바꾸거나 지울 때, 발음이 다른 짝이나 받아쓴 적 없는 단어를 넣을 때는 먼저 묻습니다. `/tidia set dict_approval ask`로 바꾸면 Claude의 사전 변경을 모두 먼저 묻습니다.
- **직접 추가.** `/tidia dict add Tailscale`, 또는 자꾸 잘못 받아써지는 말은 `/tidia dict add 테일스케일 = Tailscale`. `--project`를 붙이지 않으면 모든 프로젝트에 적용됩니다.
- **학습.** 보내기 전에 받아쓴 단어를 고쳐 치면 기억해 두고, 같은 단어를 두 번째로 고치면 사전에 추가합니다. 지우려면 Claude에게 말하거나 `/tidia dict`에서 지웁니다. `/tidia set learn off`로 끕니다.
- **초안 만들기.** `/tidia dict build`는 먼저 묻고, 이 컴퓨터에서 후보 이름을 모읍니다. 패키지·폴더 이름, git 브랜치, README와 CLAUDE.md의 이름, 그리고 동의했을 때만 이 프로젝트의 지난 대화에서 내가 자주 쓴 말. 읽는 건 모두 로컬에서 하고, 세션이 쓰는 Anthropic 연결로 모델 호출 한 번에 후보 단어만 보냅니다. 창에서 승인하기 전에는 아무것도 추가되지 않습니다.
- **대화 속 이름.** 최근 메시지의 파일 이름과 식별자도 힌트로 갑니다. React 이야기 중이면 "유즈 이펙트"가 `useEffect`로 돌아옵니다.

사전은 모든 프로젝트용 최대 2000개, 프로젝트마다 최대 2000개이고, 받아쓰기 한 번에 힌트는 최대 20개까지 갑니다.

## 출력 규칙

출력 규칙은 받아쓴 메시지를 어떻게 쓸지 정리 모델에게 주는 모든 지시입니다. 배치("번호 단계, 끝에 한 줄 요약"), 어투와 표현("존댓말로", "느낌표 없이"), 상황별 형식이 모두 여기에 들어갑니다. 조건이 없는 규칙은 항상, 조건이 있는 규칙("버그 얘기일 때")은 정리 모델이 그 조건이 맞다고 볼 때만 적용됩니다. Claude에게 말해서 만듭니다. "버그 얘기할 땐 증상, 재현, 기대 순서로 정리해 줘." 0.1.21부터 `tone`, `tone_note`, `custom_note` 설정을 대신합니다. 업그레이드 후 첫 시작 때 저장된 어투는 해당 어투 기본 규칙으로 켜고, 저장된 메모는 규칙으로 옮기며, 무엇을 옮겼는지 알려 줍니다.

`style` 설정이 규칙보다 위에 있습니다. `polish`(기본)는 간결하게 다듬고 규칙을 적용합니다. 규칙과 간결한 어투가 다르면 규칙을 따릅니다. `minimal`은 줄글로만 쓰고 규칙을 적용하지 않습니다. 모양을 고르는 것과 정리하는 것은 모델 호출 한 번에 같이 합니다. `message_view`가 labeled·full일 때 `· 규칙 적용`은 조건이 붙은 규칙이 쓰였을 때만 붙습니다. 항상 켜진 규칙은 늘 쓰는 선택이라 따로 알리지 않습니다.

기본 규칙 7개가 들어 있고, 말하기 전에는 **꺼져** 있습니다. 버그 보고와 기능 요청은 짧은 라벨 줄로, 리뷰 요청은 대상과 볼 관점으로, 여러 작업은 번호 목록으로 정리하고, 어투는 존댓말·반말·말한 말투 그대로 중에서 고릅니다. Claude에게 말하거나("버그 보고 규칙 켜 줘", "받아쓰기는 존댓말로 정리해 줘") `/tidia dict` 창에서 켭니다.

규칙은 말한 것을 정리할 뿐입니다. 규칙에 적힌 문구(라벨, 직접 정한 맺음말)는 붙일 수 있지만, 말하지 않은 요청이나 사실은 넣지 않습니다. 그런 응답은 버리고 원문을 보냅니다. 규칙은 모든 프로젝트 또는 이 프로젝트에 적용되고, `minimal` 스타일에서는 적용되지 않습니다. 규칙을 추가·변경·삭제할 때는 먼저 묻습니다. 단, Claude Code 권한 모드가 Tidia 도구를 이미 허용했다면 묻지 않습니다.

## 번역

문구는 영어, 한국어, 일본어, 중국어, 스페인어, 독일어, 프랑스어, 포르투갈어로 나옵니다. 영어와 한국어는 직접 썼고, 나머지는 원어민 검토 전까지 기계 번역 수준입니다. 고칠 곳은 `src/i18n.ts`에 pull request로 보내 주세요.
